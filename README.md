# 房屋账本（House Ledger）

房东自用的房屋 Utility 账单管理工具。以记录、理解、比较用量和费用为主，房租管理为辅助。不需要编译，可部署到 GitHub Pages。

界面支持简体中文、繁體中文（台灣）和 English，在「设置 → App 设置 → 语言与外观」切换。繁体版使用台湾常用词汇和西元日期；姓名、备注、原始账单文字及美元金额、用量单位保留原样。

## 两个主入口

- **账单**：最新 PG&E、市政、网络账单；电力、燃气、水、污水、垃圾和网络各自的历史柱状图、原始服务期和记录。用量与费用分别画图；电力费用按输配费与发电费堆叠，账单详情显示同一公司各分项的历史费用构成，不把不同公司账单强行归入统一「本期」。原来的独立「对比／季节」入口已整合。
- **住户**：住户信息、月租、房租应收与收款、历史记录。房租收入只统计明确归为房租的付款，Utility 不进入房租台账。旧版未分类收款保留待核实。

设置页顶部为独立的「当前房屋」资料；下方依次为「App 设置」「账单设置」「住户设置」。同步、语言、外观、备份与隐私说明归 App 设置，账单方与历史 PDF 关联归账单设置，默认房租规则归住户设置。目前数据模型仍管理一套房屋，修改名称不会切换或创建另一套房屋账本。原有链接仍可打开：`overview`、`analysis` 转到账单，`collect`、`residents` 转到住户。

每位住户在「编辑住户」中单独设置租期起算日、交租日和约定生效日期。自然月填 1，16 日起算则覆盖 16 日至次月 15 日；交租日可在常规租期起算月的上月、当月或下月。短月取月底。首末期按居住日期截短，但交租月份保留常规周期的基准，不随实际入住月份后移。例如 10 月 1 日入住、16 日起算、当月 15 日交租：首期 9 月 15 日交，覆盖 10 月 1 日至 10 月 15 日；下一期 10 月 15 日交，覆盖 10 月 16 日至 11 月 15 日。已保存的租期仍可单独更正。

编辑住户按「住户资料与居住日期」「房租待收统计」「月租金额」「交租与覆盖日期」分组。待收统计紧接居住信息，独立于租约：可选择从入住日开始、从指定日期开始或暂不自动计算，旁边始终说明当前设置的含义；只有指定日期模式才显示日期输入。新住户默认从入住日开始，旧住户保留原设置。月租金额与其生效日期直接显示；交租约定的生效日期另列，不混淆。该日及以后开始的租期自动生成应收；不会将跨越该日的旧租期截短。留空时不自动生成应收，仍可手动添加租期、收款和历史记录。修改跟踪日期保留已保存的租期与收款，历史补记不会再次自动生成应收。旧版开账月份读入时转为各住户的独立日期，保留原计算范围；没有旧开账月份时保持未设置。设置页不再提供全局开账入口。

住户详情只保留一份按租期排列的「房租记录」：覆盖日期、约定交租日、应收、净实收和状态。统一通过「记收支」记录每笔实际收款或退款，再明确分配到已有租期、新增租期或押金；房租覆盖日期也可稍后补。表格增加实际到账日期和支付方式，分次收款及退款按相同顺序逐条对齐；缺少日期或方式时标明待补。表格可横向、纵向滚动，表头固定。覆盖日期左对齐，金额列右对齐，到账日期、支付方式和收租状态居中，表头与对应内容一致；单行及多行记录的文字和状态标签统一为 15px。点开一期开启该期明细；收款、退款、加收减免及备注都在其中处理，不再平行展示整份流水。一笔合并付款或退款可以分给多个租期及押金，分配合计必须等于该笔总额。提前、分次付款或退款只影响明确分配到的租期。已保存应收不随住户约定后台重算；未分配收款不按到账月份猜租期。

所有房租在住户详情的「房租记录」统一新增和编辑，不按导入来源或自动统计起点分栏。约定交租日、覆盖日期（含结束日）、应收、收款确认、实收、到账日期与备注分别保存，未知可留空。同月可有多条不重叠记录；手动记录覆盖相同范围的自动候选，避免重复应收。旧字段兼容读取，旧的未知应收不从月租或实收倒推；保留原 id、批注与关联。旧的收款确认兼容读取；只有用户编辑或删除它时才转为独立收款明细，以固定 id 去重，不重复统计。新记录不再提供另一套内含收款确认输入。

「编辑本条记录」统一编辑覆盖日期、基础应收、加收减免和备注，一次保存；取消不写入调整。加收与减免保留各自金额、说明和原 id，移除此项后保存会移到最近删除。编辑房租记录时，「基础应收」可按完整约定周期的实际天数与当时月租预填，并显示计算式。覆盖结束日计入天数，不再按住户搬出日截短手填区间。跨周期、月租变更分别计算；沿用按天折算或收整期设置。缺少日期、对应租期约定或历史月租时不猜金额。自动模式随覆盖日期更新，手填后保留手填值，可点「使用计算金额」恢复。计算方式随记录保存；旧的已填应收默认保留原值，只有编辑并保存才更新记录，不后台重算历史。额外加收、减免及最终应收另行显示，收款和退款不参与应收计算。

住户首页统一按实际到账自然月展示收入，只有实收金额和到账日期已确认后计入。待补日期或金额的记录按住户列出，不用租期推算到账月份。收款或退款编辑中可明确选择「日期无法查证，不再补录」：保留空日期与该标记，金额仍计入关联租期；不再仅因缺少日期显示待补全，也不再列入日期待补记录，但不计入按到账月份统计。金额或覆盖日期仍不完整时继续显示待补全；以后查到实际日期可取消勾选再填写。收款或退款明确选择类型，金额均填写正数，退款以负数保存。调整用于改变租期应收，可关联任何房租记录；应收未知时保留调整但不推算余额。未设置租期或收款归属待确认时不显示已结清；待分配收款不计入已确认逾期待收。

「编辑房租记录」可以删除任何租期，包括尚未保存的自动租期；删除快照会阻止该范围再次自动生成。「设置 → App 设置 → 数据 → 最近删除」可恢复账单、住户、房租记录、房租收款、调整和整条导入备注。房租列表不显示删除按钮；点开租期后，在「更多 → 删除本条房租记录」操作，未关联租期的收款则从编辑窗口底部删除。删除整条租期会把租期及仅属于该行的收款、退款和调整一并移到最近删除。跨期或包含押金的共享转账会保留，受影响的房租部分待重新分配；恢复租期后自动对应回原 id。删除整笔共享转账则一起删除所有分配，最近删除或撤销可恢复整笔。撤销可一起恢复，也可在最近删除分别恢复，沿用原 id；不影响其他租期和住户。新版删除保留完整记录，不自动清除；批注和当前设备的 PDF 关联保持。旧版只有 id 的删除标记需要删除前的 JSON 备份，在「从备份找回」中逐条恢复，不用整份旧数据覆盖当前账本。清空设备数据仍需事先备份。


每笔实际收支只保存一个总额、日期、支付方式和备注；分配项分别保存房租租期或押金及其金额。只在用户保存时将旧的单期收款转换为同 id 的分配记录，读入或查看不批量改账；历史备注与来源保留。原来的合并收款需要按实际用途重新分配，不按金额猜测押金或月份。

押金在住户详情独立显示已收、已退和余额，不进入房租应收、实际收入图表或欠租。房租部分仍按实际收款日期统计；押金及退押金独立核算，空日期和「无法查证」选择沿用原规则。一笔转账从任一租期或押金明细编辑时，都回到完整总额及全部分配，避免把部分金额当作整笔。

顶部「房租账面持平」表示已知房租总额相抵，不代替逐期分配结果。同一住户同时有各期待收和多收时，显示净额并列出两者，提示调整款项分配；不称作租期待核对，也不直接把各期未抵的合计列为已确认逾期。分配正确后，各期与顶部正常显示结清。

## 账单与字段

上传或拖入 PDF，在本机识别为草稿，核对并保存账单后，原始 PDF 副本也会关联到该记录。支持 PG&E、City of Sunnyvale、AT&T Fiber 和历史 Xfinity。旧版 PG&E 的乱码文字层需要本机 OCR 或粘贴文字，原始 PDF 仍可正常预览。

每组柱子对应一张账单，横轴显示出账年月并可横向滚动，保留每张账单的标签，纵轴刻度固定可见。柱宽和间距随图表宽度调整，每屏最多显示 12 张账单；默认展示最近 12 张，月度账单约覆盖 12 个月、双月账单约覆盖 24 个月。可选择最近 24 张或全部账单，再向左查看早期记录；窄屏日期竖排以避免重叠。提示和历史表显示准确的服务起止日。历史表始终显示全部账单，账单张数筛选仅控制图表。历史表的开始、结束和出账日期分别列出，统一为 YYYY-MM-DD。不同账单天数可能不同，不能把费用总额的差异直接当作用量变化。缺失用量保留为空，不记成 0。

用量与费用图上下排列。历史表从左到右为加粗着色的账单日期、普通字体的服务开始与结束日期。最新用量和费用标明完整服务日期、计费天数及整期合计；日均费用标明金额除以计费天数的计算式。

图表可切换「整期总量」与「日均同期对比」。与去年同期比较时，按各项目自己的服务期向前平移一年，跨账单时按天均摊，要求参考区间完整覆盖且无重叠。缺失用量或金额分别保留为空；去年同期为 0 时不算百分比。去年同期是按天折算的估算，不是逐日实测用量。历史迁移金额沿用原表，可能与 PDF 中当期费用、抵扣或应付余额的口径不同，不自动改写。

柱宽采用账单位宽度的 2/3，最大 48px；同比两柱共享该宽度，组内间隔 4px，窄屏缩至 2px。参考 [Dell 柱状图规范](https://delldesignsystem.com/data-visualization/bar-chart/simple-bar-chart)的柱间距约为柱宽一半，以及 [欧盟数据可视化指南](https://data.europa.eu/apps/data-visualisation-guide/bar-size-and-spacing)对柱宽与留白平衡的说明；像素上限是本 App 的布局选择。

账单操作区统一使用标准按钮。「到期日历提醒」下载日历文件，手动导入后可在到期前 3 天提醒；已过期、已缴或缺少到期日时显示禁用原因，不自动写入日历。

「这些项目是什么意思？」可展开查看字段含义：

- PG&E 三个金额：**电力输配费用、发电费用、燃气费用**，单位都是 USD。用电量为 kWh，燃气用量为 therm。
- Sunnyvale 三个金额：**供水、污水处理、垃圾服务费**，单位都是 USD。供水另有 CCF 用量，水费含水表服务费和按量收费。
- Sunnyvale 同一张账单的水表周期可能与污水／垃圾服务期不同，新解析器分别保留。旧记录未补齐分项周期时明确显示缺失，不套用水表日期。
- 平均费用单价是金额除以用量，包含已记录的固定费、优惠和调整，不等同于供应商费率。

历史金额和锁定分摊保留原样。原来的分摊规则移到详情的折叠区，不与房租混算，不提供主导航中的对外沟通流程。

目前项目分类固定为六项 Utility，不会因为导入地税而自动新增分类；地税需另行加入房屋支出模型和解析，按税年及分期统计，避免进入 Utility 用量对比。

## 原始 PDF

账单详情可直接预览关联的原始 PDF、翻页和下载原文件。历史账单在「设置 → 账单设置 → 原始账单 PDF」批量关联；有原始 SHA-256 时核对内容，旧记录按唯一原文件名匹配，重名、未匹配和附件冲突的文件跳过，不新增账单。也可以在单张账单详情中关联或重新关联。

PDF 副本保存在当前浏览器站点的 IndexedDB，独立于账单 JSON，不进入 GitHub 同步或 JSON 备份。原文件保留在原文件夹；更换设备、站点或清理浏览器数据后需要重新关联。「清空这台设备」同时清理本机 PDF 副本。

账单、住户及租期中的导入备注和回复都可单独编辑或删除，保留作者、日期、来源及所属记录。删除回复不改变其他段落；部分删除可在原备注中恢复，整条删除可到「最近删除」恢复。手写备注也提供就地编辑与删除，删除后可撤销。修改或删除后重复导入旧文件，不会覆盖 App 内的新版本。

## Numbers 历史迁移与批注

`Shared Utilities.numbers` 只读，不修改原件。转换结果含姓名和金额，应放在仓库外。

```sh
python3 -m venv /tmp/house-ledger-numbers
/tmp/house-ledger-numbers/bin/pip install numbers-parser==4.22.0
/tmp/house-ledger-numbers/bin/python tools/dump-numbers.py "/path/Shared Utilities.numbers" /tmp/dump.private.json
```

导出同时保留值、公式、批注原文、作者、时间、回复，以及 sheet/table/cell 坐标。使用公开的 `rows()` 读取原始行，避开旧分类行映射异常，无须修改依赖库。

首次迁移可继续使用：

```sh
node tools/migrate-numbers.mjs /tmp/dump.private.json /tmp/house-ledger-import.private.json /tmp/extract /path/config.private.json
```

已导入过旧账本时，生成**只补批注和分项周期**的文件，不覆盖现有账单金额、住户和付款：

```sh
node tools/extract-pdfs.mjs "/path/Sunnyvale Utility Bill Pay" /tmp/city-extract
node tools/import-source-notes.mjs /tmp/dump.private.json /path/house-ledger-import.json /tmp/house-ledger-source-notes.private.json /tmp/city-extract
```

在「设置 → App 设置 → 数据 → 导入文件」选择补充文件。批注独立存储、逐条合并，可重复导入；账单批注与手写备注一起显示在对应账单详情的「备注」，房租及住户批注留在各自记录中。设置页不再汇总批注；原文、作者、时间、回复及来源仍保留在数据中。NA/空白单元格上的批注关联到住户和原表期次，不伪造付款。

原表房租勾选只有付款状态，没有完整金额。图表只展示已确认日期与金额的实际收款，不从批注文字自动推断金额、日期或币种。

## 数据、同步与兼容

数据保存在浏览器；可选 GitHub 私有仓库同步。令牌只留本机，不写入备份。新加的 `comments` 和 `servicePeriods` 集合参与现有合并和备份，旧版也会保留未知集合。

同步按整条记录的修改时间取较新版本：不同记录可合并；同一记录同时修改可能覆盖另一份修改，不能视为字段级冲突合并。

真实 PDF、Numbers、JSON、批注和备份不应提交到代码仓库；`.gitignore` 已排除。离线缓存文件版本已更新。
